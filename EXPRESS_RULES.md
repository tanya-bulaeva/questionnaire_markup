# Правила режима Экспресс

Режим `Экспресс` предназначен для коротких анкет, обычно на 7-8 вопросов. В интерфейсе включается отдельным чекбоксом.

## Структура анкеты

- Ожидаются простые коды вопросов: `Q1`, `Q2`, `Q3` и т.д.
- В режиме `Экспресс` весь текст до первого найденного вопроса игнорируется и не попадает в скрипт.
- Служебные intro-строки вида `Нетаргетированный экспресс опрос`, `Таргетированный экспресс опрос`, `Нетаргетированный ЭО`, квоты, название проекта, тема опроса и строки с префиксами `ES:`, `OS:`, `BL:`, `BLS:`, `FMCG:`, `AUTO:`, `OMNI:`, `OMNIBUS:` не должны становиться вопросами, вариантами или инструкциями.
- Если номер вопроса пропущен, должно появиться предупреждение вида `Экспресс: пропущен QN`.
- Основные типы вопросов: `Single` и `Multi`.
- Для `Single` и `Multi` должны быть варианты ответа.
- Варианты в экспрессах должны быть пронумерованы. Произвольные строки без номера не должны получать автокоды.
- Если варианты оформлены Word-нумерацией, номер списка нужно учитывать как реальный код варианта.
- Если вопросы в анкете идут числовыми заголовками `1.`, `2.`, `3.` без `Q`, в экспрессе они нормализуются в `Q1`, `Q2`, `Q3`.
- Строки условий вида `Q4 для тех, кто...` перед настоящей формулировкой не считаются отдельным вопросом.

## Распознавание типа

- `один ответ`, `один вариант ответа`, `одиночный выбор` -> `Single`.
- `множественный`, `несколько ответов`, `до N вариантов`, `не более N`, `максимум N`, `макс. N` -> `Multi`.
- Если варианты есть, но явного типа нет, по умолчанию используется `Single`, кроме случаев, где уже распознан `Multi`.

## Служебные строки

Эти строки не должны становиться вариантами ответа:

```txt
Один вариант ответа
Дополнительный разрез
Дополнительный разрез в шапке
```

## Очистка вариантов

Из текста варианта удаляются служебные хвосты:

```txt
открытый / открытый вопрос
эксклюзив / эксклюзивный
complete / комплит
закончить комплитом
завершить complete
завершить опрос со статусом “complete”
завершить опрос со статусом “
доп разрез
цветные span/font-пометки
```

Кавычки в тексте анкеты сохраняются в TXT-скрипте как обычные кавычки. HTML-сущности `&quot;`, `&#34;`, `&#039;`, `&apos;` не должны оставаться в экспортируемых заголовках, вариантах, строках и колонках.

## Other / Exclusive / Fix

- `открытый` / `открытый вопрос` удаляется из текста и дает `other: yes`.
- `эксклюзив` / `эксклюзивный` удаляется из текста и дает `exclusive: yes` для `Multi`.
- `other: yes` ставится только для явно открытого варианта `Другое`, где есть маркер `укажите`, `уточните`, `напишите` или `открытый`.
- `Другое - открытый`, `Другое - открытый ответ`, `Другое - открытый вопрос` дают `other: yes`; хвост `открытый...` удаляется из текста варианта.
- Простое `Другое` без указания на открытый ответ не получает `other: yes`.
- В `Single` для варианта типа `Затрудняюсь ответить` не нужно выводить `exclusive: yes`.
- В `Single` без ротации для `Другое` не нужно выводить `fix: yes`; остается только `other: yes`.
- В `Multi` без ротации для эксклюзивного варианта не нужно выводить `fix: yes`.
- Если один и тот же вариант получил `fix: yes` по нескольким правилам, строка `fix: yes` должна выводиться только один раз.

## Complete

Пометки `complete`, `комплит`, `закончить...`, `завершить...` удаляются из текста варианта.

Завершение оформляется через `after: <code>`.

Для `Single`, один код:

```txt
if (${$q->questionCode}==N) $q->finish('complete');
```

Также распознаются инструкции, где комплит указан не в тексте варианта, а в служебной строке вопроса:

```txt
при выборе 23 завершить со статусом “комплит”
при выборе кода 23 complete
код 23 закончить комплитом
```

Для `Single`, несколько кодов:

```txt
if (in_array(${$q->questionCode},[N1,N2])) $q->finish('complete');
```

Для `Multi`, один код:

```txt
if (in_array(N,${$q->questionCode})) $q->finish('complete');
```

Для `Multi`, несколько кодов:

```txt
if (count(array_intersect(${$q->questionCode},[N1,N2]))) $q->finish('complete');
```

## Max

Для `Multi` распознаются формулировки:

```txt
до N вариантов
до N ответов
не более N вариантов
не более N ответов
максимум N вариантов
максимум N ответов
макс. N
макс N
(макс.N)
множественный ответ до N вариантов
множественный выбор до N вариантов ответа
```

`N` может быть числом или русским числительным от 1 до 10:

```txt
один / одного / одну
два / две / двух
три / трех / трёх
четыре / четырех / четырёх
пять / пяти
шесть / шести
семь / семи
восемь / восьми
девять / девяти
десять / десяти
```

Примеры:

```txt
До двух ответов -> max: 2
Множественный выбор до трех вариантов ответа -> type: Multi + max: 3
Не более пяти вариантов -> max: 5
```

В экспорт идет только:

```txt
max: N
```

## Ротация

Обычная ротация:

```txt
optionsOrder: randomize
```

Если в инструкции указано `ротация кроме кода 13 и 14`, коды `13` и `14` должны получить `fix: yes`.

Если в инструкции указано `ротировать кроме кодов 32-34`, диапазон должен разворачиваться в коды `32`, `33`, `34`, и каждый из них должен получить `fix: yes`.

Если в инструкции указано `ротация 1-8` без слова `кроме`, ротируются только варианты `1-8`; все остальные варианты получают `fix: yes`.

Если в анкете есть опечатка слитного диапазона вида `312-33`, она трактуется как `31-33`, и коды `31`, `32`, `33` получают `fix: yes`.

Пример:

```txt
Q1. Кем вы работаете?
type: Multi
optionsOrder: randomize
options:
1. IT-специалисты
2. Сотрудники маркетинга и PR
32. Другое
other: yes
fix: yes
33. Не работаю в штате компании или предприятия
fix: yes
34. Не работаю
fix: yes
```

Групповая ротация работает как в основном проекте: через `before: <code>`.

Пример:

```txt
optionsOrder: randomize
before: <code>
//массив с группами вариантов, которые нужно ротировать единым блоком
$groups=[
    1000 => [1,2,3],
    1001 => [4,5],
];
$lastOptions=[99];
$rotateOptions=array_diff($q->viewed(), $lastOptions, array_merge(...$groups));
array_splice($rotateOptions, 0, 0, array_keys($groups));
shuffle($rotateOptions);
foreach($groups as $key => $group) {
    shuffle($group);
    $offset=array_search($key, $rotateOptions);
    array_splice($rotateOptions, $offset, 1, $group);
}
$order=array_merge($rotateOptions, $lastOptions);
$q->orderviewed($order);
</code>
```

## Condition

В экспрессе `condition` экспортируется как:

```txt
condition: ...
```

В одном вопросе должна быть только одна строка `condition:`. Если условий несколько, они объединяются в одну строку:

```txt
condition: ($Q1==1) && ($Q2==2)
condition: in_array($Q6,[1,2,3]) || in_array(9, $Q3)
```

Обязательные условия объединяются через `&&`. Альтернативные пути показа, например переход из другого вопроса, объединяются через `||`.

Условие не должно ссылаться на текущий вопрос. Например, для `Q6` нельзя выводить:

```txt
condition: in_array($Q6,[1,2,3])
```

Такое условие может применяться только к вопросам после `Q6`.

Естественные формулировки условий преобразуются в PHP-условие:

```txt
Q4 для тех, кто выбрал коды 1, 3, 4 в Q2
-> condition: in_array($Q2, [1, 3, 4])

Q5 для тех, кто выбрал коды 2, 3, 4 в Q2
-> condition: in_array($Q2, [2, 3, 4])
```

Если такая строка стоит перед заголовком вопроса, она не должна создавать отдельный вопрос; она относится к вопросу с кодом в начале строки.

Если условие стоит прямо в заголовке после формулировки, например `Q4. ...? Для Q3 = 1, 2, 6`, формулировка остается только до вопросительного знака, а условие выводится отдельной строкой `condition: ...`.

В обычном режиме условия показа также экспортируются через `condition:` по правилам `MAIN_RULES.md`.

## Переходы

В express-анкетах переход может быть записан хвостом варианта:

```txt
9. Ничего не покупал(а) - переход к Q7
9. Ничего не покупал(а) - перейти к Q7
9. Ничего не покупал(а) - переход на Q7
```

Хвост `переход к/на/в Q...` удаляется из текста варианта.

Если вариант ведет к более позднему вопросу, промежуточные вопросы получают условие, что этот вариант не был выбран.

Для `Single`-источника:

```txt
condition: $Q3!=9
```

Для `Multi`-источника:

```txt
condition: count(array_diff($Q3, [9]))
```

Целевой вопрос получает альтернативное условие, что код перехода был выбран.

Для `Single`-источника:

```txt
condition: $Q3==9
```

Для `Multi`-источника:

```txt
condition: in_array(9, $Q3)
```

Если у целевого вопроса уже есть свое условие, оно объединяется с переходом через `||`.

Пример:

```txt
Q3 вариант 9: Ничего не покупал(а) - переход к Q7
Q7 для тех, кто выбрал коды 1-3 в Q6
```

Ожидаемый экспорт:

```txt
condition: in_array($Q6,[1,2,3]) || in_array(9, $Q3)
```

## Что не выводится в Экспресс

В режиме `Экспресс` отключен экспорт:

```txt
html1
html2
holdRow: yes
QCONTROL
```

`html3` является исключением: он может выводиться для дисклеймера Meta, если в анкете есть упоминание Meta-продукта или готовый текст дисклеймера.

Даже если в интерфейсе отмечен GEO-чекбокс, GEO-настройки и GEO-текст не выводятся в третью колонку и не экспортируются для express-проекта.

Режим `Экспресс` не генерирует автоматически служебную production-обвязку, если она отсутствует в Word-анкете:

```txt
quotafilter TOTAL
Qredirect
before: <code>if ($q->vars->ank)...</code>
```

## Инструкции и заголовки

- Цветные служебные `span` / `font color` удаляются из заголовков.
- Цветные служебные инструкции не попадают в `// instruction:`.
- Нормальные инструкции могут выводиться как `// instruction: ...`.
