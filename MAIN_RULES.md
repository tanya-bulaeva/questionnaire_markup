# Правила основного проекта

Основной проект - это обычный режим приложения без включенного чекбокса `Экспресс`.
Он предназначен для подготовки Word-анкеты к экспорту в TXT-структуру.

## Общая логика

- Исходный `.docx` не изменяется.
- Приложение работает локально в браузере, без backend и без загрузки файлов во внешние сервисы.
- Основной рабочий файл приложения: `index.html`.
- Пользователь загружает `.docx`, проверяет найденные вопросы, при необходимости правит роли блоков и экспортирует результат.
- Экспортируются:
  - размеченный `.docx`;
  - TXT-скрипт.

## Границы вопросов

- Поддерживается ручной маркер начала вопроса:

```txt
###Q###
```

- Если `###Q###` есть в DOCX, он считается началом нового вопроса.
- Предыдущий вопрос при встрече маркера автоматически заканчивается.
- Сам маркер `###Q###` не попадает в экспорт.
- Если маркеров нет, используется автоопределение границ вопросов.
- Код вопроса ищется в начале вопросного блока.
- Служебные блоки без содержимого для скрипта не экспортируются.
- Вопрос со статусом `ignored` не экспортируется.

## Роли блоков Word

Блокам можно назначать роли:

```txt
before
after
title
instruction
condition
option
options table
headings
ignore
clear
```

- `title` идет в заголовок вопроса.
- `instruction` в основном режиме экспортируется как комментарий:

```txt
// instruction: ...
```

- `condition` используется только для условий показа/доступности вопроса и экспортируется активной строкой:

```txt
condition: ...
```

- Строки с действиями после ответа (`скрин`, `завершить`, `переход`, `goto`, `skip`, `terminate`) должны относиться к `after`, а не к `condition`.
- `before` без ручного кода экспортируется в `before: <code>` строками с префиксом `///`.
- `after` без ручного кода экспортируется в `after: <code>` строками с префиксом `///`.
- `option` становится вариантом ответа.
- `options table` разбирается как таблица вариантов/строк/колонок, если возможно:
  - для обычных `Single`/`Multi` из таблицы извлекаются варианты ответа в `options:`;
  - для `Matrix`/`Grid` строки таблицы могут стать `headings:`, а шкала/колонки - `options:`;
  - явные числовые коды в таблице сохраняются как коды вариантов/строк/колонок;
  - служебные колонки с условиями или логикой показа не должны попадать в текст вариантов, но могут использоваться для `condition`, `before` или `after`;
  - если таблицу нельзя однозначно разделить на варианты, строки и колонки, вопрос требует ручной проверки.
- `headings` используется для строк матрицы/грида.
- `ignore` исключается из содержимого вопроса.
- `clear` снимает ручную роль с блока.
- Перед экспортом TXT приложение пересобирает вопросы из текущих ролей блоков, чтобы последние ручные изменения `title`, `option`, `condition`, `after`, `instruction`, `headings` попадали в экспорт.

## Коды вопросов

- Используется нормализованный код вопроса, если он есть.
- Если нормализованного кода нет, берется исходный код.
- Если в DOCX вопрос начинается только с числа, например `2. Какие из перечисленных сервисов вам известны?`, это допустимый числовой код вопроса.
- При разметке DOCX и скачивании скрипта числовой код вопроса нормализуется с префиксом `Q`:
  - `2` -> `Q2`;
  - `10` -> `Q10`;
  - `2.1` -> `Q2p1`;
  - `2_1` -> `Q2p1`.
- Числовые коды вопросов нужно отличать от числовых кодов вариантов ответа: внутри уже найденного вопроса строки вариантов не должны превращаться в новые вопросы.
- Для `Info`-блоков:
  - пустой код превращается в `QINFO`;
  - код `INFO...` превращается в `QINFO...`;
  - прочие коды получают префикс `QINFO_`.
- Примеры нормализации из базовых правил:
  - `S1` -> `QS1`;
  - `D4.1` -> `QD4p1`;
  - `Q1_2` -> `Q1p2`.

## Типы вопросов

Поддерживаемые типы:

```txt
Single
Multi
Free
Matrix
Grid
Rank
Scale
Info
Group
```

- Если вопрос похож на выбор и есть варианты, по умолчанию используется `Single`.
- Если явно распознан множественный выбор, используется `Multi`.
- Если нет вариантов и текст короткий, вопрос может быть `Info`.
- Если тип не распознан, ставится `Unknown` и требуется проверка.
- Для вопроса про пол тип принудительно экспортируется как `Single`.

## Скрытые автокодируемые вопросы

- Для DOCX-разметки специальные скрытые вопросы `QINCOMEGROUPS`, `QINCOMEGROUPS1`, `QINCOMEGROUPS2`, `QTVGROUPS` распознаются по коду вопроса или по служебному тексту в анкете.
- Если в анкете найдено `INCOMEGROUPS`, `QINCOMEGROUPS`, `INCOMEGROUPS1`, `QINCOMEGROUPS1`, `INCOMEGROUPS2`, `QINCOMEGROUPS2`, `TVGROUPS` или `QTVGROUPS`, приложение принудительно использует соответствующий лейбл `Q...`, даже если рядом был распознан другой авто-лейбл вроде `Qp7`.
- Служебный лейбл из текста не должен переименовывать обычный source-вопрос с нормальным кодом вроде `QS4`, даже если служебный текст попал в его контекст.
- В TXT такие вопросы экспортируются со стандартным заголовком, а не с найденным служебным словом как текстом вопроса.
- Такие вопросы нужно проверять вручную: приложение не всегда может уверенно определить источник автокодирования и корректность логики.
- Эти вопросы экспортируются как `type: Single`.
- Текст `НЕ ПОКАЗЫВАТЬ РЕСПОНДЕНТУ. ЗАКОДИРОВАТЬ КАК:` не требует ручной роли `before`: приложение само формирует `before: <code>`.
- `QINCOMEGROUPS`, `QINCOMEGROUPS1`, `QINCOMEGROUPS2` используют источник дохода из первой найденной ссылки вида `S4=...` / `QS4=...`:
- Если в `before` скрытого автокодируемого вопроса используется лейбл вопроса, этот вопрос должен быть в TXT-скрипте. Если источник не найден среди экспортируемых вопросов, скрытый вопрос требует ручной проверки.
- Если source-вопрос найден в разметке, но был пропущен обычным экспортом, приложение принудительно выгружает его перед `QINCOMEGROUPS` / `QTVGROUPS`.

```txt
$ans='';
if (in_array($QS4,[1,2])) $ans=1;
elseif ($QS4==3) $ans=2;
elseif ($QS4==4) $ans=3;
else $ans=4;
$q->answer($ans)->next();
```

- Для этих income-вопросов варианты фиксируются так:

```txt
1. Низкий доход
2. Средне-низкий доход
3. Средне-высокий доход
4. Высокий доход
```

- Для `QTVGROUPS` источник может быть указан разными лейблами в условиях анкеты, например `S6.1=...`, `S6.2=...`, `QS5.1=...`, `QS5.2=...`, `QTV1=...`, `QTV2=...`.
- Ссылки на source-вопросы нормализуются по общим правилам кодов вопросов:

```txt
S6.1 -> QS6p1
S6.2 -> QS6p2
QS5.1 -> QS5p1
QS5.2 -> QS5p2
```

- Если используются парные под-вопросы, они должны быть согласованной парой одного базового вопроса. Например, можно использовать `QS6p1` и `QS6p2` или `QS5p1` и `QS5p2`, но нельзя случайно смешивать `QS5p1` и `QS6p2`.
- Основная логика `QTVGROUPS` строится из условий в скобках у вариантов самого `QTVGROUPS`.
- Если условия в вариантах распознаны, приложение строит `before: <code>` из этих условий, а текст вариантов очищает от условий в скобках.
- Пример:

```txt
1. Heavy TV viewers (Q8=1 и Q8.1=1)
```

Ожидаемый фрагмент:

```txt
$ans = '';
if (($Q8 == 1 && $Q8p1 == 1)) $ans = 1;
$q->answer($ans)->next();
```

- Если условия в вариантах `QTVGROUPS` не удалось распознать, экспортируется заглушка:

```txt
before: <code>
$ans = '';
if () $ans = 1;
elseif () $ans = 2;
elseif () $ans = 3;
$q->answer($ans)->next();
</code>
```
- Для `QTVGROUPS` варианты фиксируются так:

```txt
1. Heavy TV viewers
2. Medium TV viewers
3. Light TV viewers
```

- Если источник не найден в тексте DOCX, для income-групп используется fallback-источник `QS4`, а вопрос нуждается в обязательной ручной проверке.
- Для `QTVGROUPS` отсутствие распознанных условий в вариантах означает заглушку `if () / elseif ()` и обязательную ручную проверку.

## Базовая структура TXT-экспорта

Обычный вопрос экспортируется в таком порядке:

```txt
// instruction: ...
Q1. Текст вопроса
type: Single
max: N
condition: ...
optionsOrder: randomize
html1: <code>
...
</code>
html2: <code>
...
</code>
before: <code>
...
</code>
after: <code>
...
</code>
options:
1. Вариант
headings:
1. Строка
```

- Пустые секции не выводятся.
- `condition:` выводится активной строкой, а не комментарием.

## Conditions

- Условия показа экспортируются строками:

```txt
condition: ...
```

- В одном вопросе должна быть максимум одна строка `condition:`.
- Если условий несколько, они объединяются в одну строку через `&&` или `||`.
- Обязательные условия объединяются через `&&`.
- Альтернативные пути показа объединяются через `||`.
- Условие не должно ссылаться на текущий вопрос. Например, для `Q6` нельзя выводить:

```txt
condition: in_array($Q6,[1,2,3])
```

Такое условие может применяться только к вопросам после `Q6`.
- Если условие не удалось распознать, оно все равно экспортируется как активная строка с пометкой проверки:

```txt
condition: [ПРОВЕРИТЬ: исходный текст условия]
```

- Из условия удаляются начальные слова:
  - `задать`;
  - `задавать`;
  - `показывать`;
  - `показать`;
  - `если`;
  - `if`;
  - `для тех, кто`;
  - `МНОЖЕСТВЕННЫЙ ОТВЕТ`;
  - `ОДИН ОТВЕТ`;
  - лишние начальные `/`.
- Формат `Для Q...=...` нормализуется:
  - `Для Q1=1-4` -> `in_array($Q1,[1,2,3,4])`;
  - если вопрос-источник `Multi`, `Для Q2=2-3` -> `count(array_intersect($Q2,[2,3]))`;
  - один код для `Single` -> `$Q1==1`;
  - один код для `Multi` -> `in_array(1,$Q2)`.
- Формулировки с типом вопроса перед условием также нормализуются:

```txt
МНОЖЕСТВЕННЫЙ ОТВЕТ для тех, кто QS3=1
-> condition: in_array(1, $QS3)

ОДИН ОТВЕТ для тех, кто QS3=1
-> condition: $QS3==1
```

## Варианты ответа

- Вариант с явным номером имеет приоритет перед instruction.
- Word-нумерация вариантов из DOCX учитывается как реальный код варианта.
- Если у варианта нет кода, приложение не подставляет код по порядку: вариант остается без кода, а вопрос получает предупреждение `Нет кода варианта ответа`.
- Для вариантов экспортируется формат:

```txt
1. Текст варианта
other: yes
exclusive: yes
fix: yes
```

- Для вопросов с генерацией вариантов из другого вопроса основные варианты берутся из вопроса-источника.
- Хвостовые варианты, явно указанные в инструкции текущего вопроса через `+97`, `+98`, `+99`, `+999`, `+9999`, берутся из инструкции текущего вопроса, а не из вопроса-источника.
- При извлечении таких хвостовых вариантов текст обрезается до следующего `+код` или до служебных фраз вроде `РОТАЦИЯ`, `СТРОКИ`, `ПОКАЗАТЬ`, `КОНТРОЛЬ`, `ВОЗМОЖЕН ВЫБОР`.
- Если у обычного `Single`/`Multi` вопроса в инструкции есть хвостовой вариант `+97 ...`, но такого варианта нет в списке `options`, приложение добавляет его в экспорт.
- Для вопросов с формулировкой `пользуетесь` хвостовой `+97 Никакими/Ни на каких из перечисленных` добавляет screenout `after`.
- `Другое` автоматически дает `other: yes`.
- Для `Multi` код `99` автоматически дает `exclusive: yes`.
- Для `Multi` код `99` при ротации получает `fix: yes`.
- Для `Single` код `99` при ротации получает `fix: yes`, но не получает `exclusive: yes`.
- Повторная строка `fix: yes` не должна выводиться несколько раз для одного варианта.

## Очистка хвостов вариантов

В основном режиме из конца текста вариантов мягко удаляются служебные хвосты:

```txt
открытый
открытая
открытое
открытые
открытый вопрос
эксклюзив
эксклюзивный
EXCLUSIVE
доп разрез
доп разрезы
завершить
закончить
скрин
screenout
screen out
ПРОВЕРИТЬ КВОТУ
ПРОВЕРИТЬ КВОТЫ
```

- `открытый` дает `other: yes`.
- `эксклюзив` / `EXCLUSIVE` дает `exclusive: yes`.
- Пометки screenout/завершения удаляются из текста, а логика уходит в `after: <code>`.

## Max для Multi

- Для `Multi` распознаются формулировки:

```txt
не более N
максимум N
```

- В экспорт идет:

```txt
max: N
```

## Ротация

- Простая ротация экспортируется как:

```txt
optionsOrder: randomize
```

- Инструкции вида `ротация кроме кода ...` / `ротировать кроме кодов ...` дают `fix: yes` указанным кодам.
- Диапазоны разворачиваются:

```txt
32-34 -> 32,33,34
```

- Групповая ротация в основном режиме должна выводиться через `before: <code>` с:
  - `$groups`;
  - `$lastOptions`;
  - `$rotateOptions`;
  - `$q->orderviewed($order)`.
- `rotationGroups:` в TXT больше не должен использоваться для групповой ротации.

## Screenout / завершение

- Для вариантов с пометками:

```txt
завершить
закончить
скрин
screenout
screen out
```

добавляется `after: <code>`.

- Используется завершение:

```php
$q->finish('screenout', null, "NO_".$q->questionCode);
```

- Для `Single`, один код:

```php
if (${$q->questionCode}==N) $q->finish('screenout', null, "NO_".$q->questionCode);
```

- Для `Single`, несколько кодов:

```php
if (in_array(${$q->questionCode},[N1,N2])) $q->finish('screenout', null, "NO_".$q->questionCode);
```

- Для `Multi`, один код:

```php
if (in_array(N,${$q->questionCode})) $q->finish('screenout', null, "NO_".$q->questionCode);
```

- Для `Multi`, несколько кодов:

```php
if (count(array_intersect(${$q->questionCode},[N1,N2]))) $q->finish('screenout', null, "NO_".$q->questionCode);
```

- Инструкции вида `если выбран код 1 или 2 - завершить опрос` дают screenout-логику по выбранным кодам:

```txt
after: <code>
if (in_array(${$q->questionCode},[1,2])) $q->finish('screenout', null, "NO_".$q->questionCode);
</code>
```

- Для сложных инструкций вида `если НЕ выбраны варианты 2,3,4 - завершить` добавляется:

```txt
after: <code>
if (!count(array_intersect(${$q->questionCode}, [2,3,4]))) $q->finish('screenout', null, "NO_".$q->questionCode);
</code>
```

- Положительная screenout-логика не применяется к отрицательным формулировкам `не выбран` / `не отмечен`, чтобы не появлялись два противоположных `after` одновременно.

- Если коды в такой инструкции не удалось извлечь, ставится заглушка:

```txt
after: <code>
if (!count(array_intersect(${$q->questionCode}, [КОДЫ]))) $q->finish('screenout', null, "NO_".$q->questionCode);
</code>
```

- Для GEO-вопроса города/населенного пункта `after`-логика не экспортируется автоматически. Например, инструкция `если выбран 9998 - завершить` не должна превращаться в `after` для GEO-вопроса.

## Free и AI coding

- В основном режиме обычный `Free` автоматически получает дополнительный Rank-блок кодирования.
- Это не применяется в режиме `Экспресс`.
- Это не применяется к `Info`.
- Это не применяется, если для `Free` выбран один из специальных режимов открытого списка.
- Для `Free` внутри лупса и для специальных шаблонов `10 строк/полей` AI coding добавляется по правилам соответствующего шаблона.

Шаблон:

```txt
QAIcode. Текст вопроса - Кодирование
type: Rank
aiCodingQuestion: Q
aiCodingGroup: ГРУППА_КОДИРОВАНИЯ
options:
997.Брак
predefined: yes
998.Другое
predefined: yes
999.Затруднились ответить
predefined: yes
```

## Специальные шаблоны открытого списка

Для `Free` можно использовать режимы:

```txt
free
simple
exclusive
dropdown
dropdown_exclusive
```

- `free` - обычный `Free` плюс AI coding Rank-блок.
- `simple` - шаблон `10 полей`.
- `exclusive` - шаблон `10 полей + ЗО`.
- `dropdown` - шаблон `10 выпадающих полей`.
- `dropdown_exclusive` - шаблон `10 выпадающих полей + ЗО`.
- Режим открытого списка автоопределяется по формулировкам:
  - `10 полей`;
  - `10 строк`;
  - `10 ответов`;
  - `10 вариантов`;
  - `выпадающие`;
  - `dropdown`;
  - `select`;
  - `появляются по мере заполнения предыдущего`;
  - `последовательно появляющихся строк`.
- Формулировки с `+99`, `+ + 99`, `ЗО`, `99. Не знаю / затрудняюсь ответить` включают вариант шаблона с ЗО.
- Для шаблонов открытого списка генерируются связанные блоки `Matrix`, `Free`, `Group`, `Multi`, `Rank` по встроенным шаблонам приложения.
- Если в анкете явно указана формулировка `+99 ...`, она используется как текст exclusive-варианта `99` во всех шаблонах с ЗО, например `99.Не знаю / затрудняюсь ответить`.
- Если явной формулировки `+99 ...` нет, но есть вариант `99` или текст вроде `Затрудняюсь ответить` / `Ничего из перечисленного`, он используется как fallback для exclusive-варианта открытого списка.

## Лупсы

- В основном режиме поддерживаются multi-question loop: в одной итерации могут повторяться несколько вопросов из `repeat_question_ids`.
- Переход к следующему элементу лупса добавляется отдельным `...GO...` после последнего вопроса итерации.
- Для loop-вопросов типа `Grid` добавляются:

```txt
template: buttons
headingsOrder: randomize
```

- Для одиночного `Grid` внутри лупса добавляется `after`-переход.
- Ссылки на вопросы внутри итерации получают суффикс `pN`, чтобы conditions и before-код ссылались на вопрос текущей итерации.
- Ручной режим `Характеристики лупс` создает loop без обязательной фразы `генерация из`.
- В режиме `Характеристики лупс` характеристики идут в `pSTART` как `options`.
- Если в анкете указана ротация утверждений/строк, ротируются элементы лупса в `pSTART` через `$MyVar=$q->viewed(); shuffle($MyVar);`, а внутри повторяемых вопросов `optionsOrder: randomize` не добавляется.
- В каждом повторе характеристика вставляется в title как:

```html
<div style="display: none;"> - </div><div class="image">...</div>
```

- Для `Характеристики лупс` добавляется `html1` со стилями для `.image`.
- Если в options две группы с повтором кода `1`, шкала определяется эвристически.
- Шкала обычно короче списка характеристик и содержит слова вроде `согласен`, `скорее`, `абсолютно`, `оценка`, `балл`, `да/нет`.
- Характеристики не должны попадать в `options:` внутри повторяемого вопроса.
- В лупсах с генерацией вариантов из другого вопроса основные варианты берутся из вопроса-источника, а хвостовые `+97` / `+99` берутся из инструкции текущего loop-вопроса.
- Если шкала не найдена, вопрос получает предупреждение:

```txt
Loop draft: scale options were not detected, check options inside loop.
```

## GEO

- Дополнительные GEO-блоки не вставляются автоматически, если в анкете явно не написано `Qregion`, `Qdistrict`, `Qstrata` или `QstrataWI`, и пользователь не включил соответствующие GEO-настройки.
- Вопрос считается GEO-кандидатом, если в нем явно указан `Qcity` или есть формулировка вида:

```txt
В каком городе/населенном пункте Вы проживаете...
В каком населенном пункте Вы живете...
городе/населенном пункте
```

- Для GEO-вопроса приложение пытается автоматически определить шаблон города по тексту вопроса/инструкций.
- Автоматически распознаются пороги `mln+`, `700+`, `500+`, `400+`, `250+`, `100+`, `50+`, `0+ / все`.
- `0+ / все` в данных приложения хранится как `all`, но в шаблоне соответствует `0+`.
- Шаблон считается уверенно определенным только если найдены и порог, и режим Крыма: `с Крымом` или `без Крыма`.
- Если GEO-кандидат найден, но конкретный шаблон не распознан, GEO-настройки все равно включаются с дефолтами `100+` и `без Крыма`, чтобы пользователь мог выбрать настройки вручную.
- Если порог или режим Крыма не найден, используется ручной выбор в GEO UI; по умолчанию выбран `100+`.
- Если GEO-коды явно указаны в анкете, они имеют приоритет над ручными чекбоксами UI.
- Если в анкете явно написано `QDISTRICT`, `QSTRATA`, `QSTRATAWI` или похожий GEO-код в другом регистре, регистр в заголовке сохраняется.
- В GEO UI используются чекбоксы:
  - `Qstrata`;
  - `Qdistrict`;
  - `Qregion`.
- Если GEO-коды найдены в анкете, соответствующие чекбоксы отмечены и отключены.
- Видимого чекбокса `QstrataWI` в GEO UI нет, но если `QstrataWI` / `QSTRATAWI` явно указан в анкете, блок все равно генерируется.
- `QdistrictDop` сейчас не добавляется как ручной чекбокс в UI. Если соответствующий шаблон нужен, его нужно проверять вручную.
- GEO-вопрос города экспортируется как `type: Single` и получает:

```txt
template: list
search: yes
html1: <code>
...
</code>
```

- Для хвостового GEO-варианта по умолчанию используется `9999. Другой населенный пункт`.
- Если в инструкции, badge или вариантах GEO-вопроса явно указан `Другой город`, хвостовой вариант и badge используют `Другой город`.
- Если в инструкции или вариантах явно указан код `9998` для `Другой город` / `Другой населенный пункт`, используется `9998` вместо дефолтного `9999`.
- Автокодируемые GEO-блоки `Qregion`, `Qdistrict`, `Qstrata`, `QstrataWI` строятся через `before: <code>` с массивом `$city` и поиском ответа по выбранному городу.
- Если GEO-шаблон найден в `geo-templates.js`, используется готовый шаблон. Если готового шаблона нет, блок строится из `geo-data.js` / загруженного GEO XLSX.
- Для GEO-вопроса города/населенного пункта `after`-логика не экспортируется автоматически.

## Дата рождения и возраст

- Вопрос про дату рождения распознается отдельно, если в title/instruction есть `дата рождения`.
- Детские формулировки с `ребен...` / `дет...` не считаются обычной датой рождения респондента.
- Для даты рождения создается набор служебных вопросов:
  - `QDataM` - Matrix;
  - `QDataDay` - Single, список 1-31;
  - `QDataMonth` - Single, список месяцев;
  - `QDataYear` - Single, список годов;
  - вопрос с рассчитанным возрастом.
- Если следующий вопрос является возрастным интервалом, он связывается с рассчитанным возрастом.
- Если после даты рождения идет `Single` с вариантами, похожими на возрастные диапазоны, он тоже считается возрастным интервалом, даже если в заголовке нет слов `возрастной интервал`.
- Если в анкете явно указан лейбл для возрастного интервала, в экспорте используется этот лейбл без добавления `age`, например `QS2a. ВОЗРАСТНОЙ ИНТЕРВАЛ`.
- Если отдельного явного лейбла возрастного интервала нет, код формируется от лейбла вопроса про дату рождения с суффиксом `age`, например `QS3age. ВОЗРАСТНОЙ ИНТЕРВАЛ`.
- Отдельный вопрос возрастного интервала после даты рождения не экспортируется как самостоятельный обычный вопрос.

## Вопрос про пол

- Если в тексте вопроса/инструкций/вариантов есть `пол` и варианты `мужской`/`женский` или `мужчина`/`женщина`, вопрос считается вопросом про пол.
- Тип принудительно экспортируется как `Single`.
- Добавляется:

```txt
columns: 2
```

- Добавляется `html1` со стилем центрирования вариантов.
- В основном режиме служебный вопрос `Qscreen` обязателен и выгружается после вопроса с возрастным интервалом.
- Для служебного вопроса `Qscreen` строка проверки пола зависит от кодировки вопроса про пол:
  - если код `1` - `женщина` / `женский`, а код `2` - `мужчина` / `мужской`, используется:

```php
$gender=($Qper[0] && $Qper[0]==$QS1 ? false : true);
```

  - если код `1` - `мужчина` / `мужской`, а код `2` - `женщина` / `женский`, используется:

```php
$gender=($Qper[0] && $Qper[0]!=$QS1 ? false : true);
```

  - если код вопроса про пол не `QS1`, в строке используется фактический код вопроса, например `$Q2` или `$QD4`.

## Картинки / логотипы в вариантах

- Если в контексте вопроса есть слова:
  - `логотип`;
  - `лого`;
  - `картинк...`;
  - `изображени...`;
  - `показать лого`;
  - `показать логотип`;
  - `показать картин...`;

то в основном режиме включается шаблон вариантов с картинками.

- Если есть инструкция вроде `Имена и названия показывать с фото/лого`, она включает шаблон вариантов с картинками только при наличии списка `options`.
- Если списка вариантов нет и речь про одиночную картинку, это правило не применяется.
- Для таких вопросов добавляется:

```txt
holdRow: yes
```

- Добавляется `html1` со скриптами/стилями для отображения картинок и отдельной раскладкой последнего варианта.
- Варианты с картинками получают плейсхолдер:

```html
<img src="/uploads/surveys/{номер проекта}/logo_{код}.jpg">Текст варианта
```

- Номер проекта берется из поля `Номер проекта`.
- Если номер проекта не задан, используется `XXXX`.
- Служебные коды `97`, `98`, `99`, `999`, `9999` не получают картинку.
- Если в варианте уже есть `<img>`, второй `<img>` не добавляется.
- Для генерации вариантов из другого вопроса с логотипами `html1` ставится перед `before`, затем идут `options`.
- Для source/options с картинками используется шаблон `answersWithImageU`.
- Если в вопросе две строки `exclusive: yes` и есть картинки в вариантах, используется специальная раскладка для двух последних исключающих вариантов.
- Для одиночной картинки по фразам `показываем лого`, `показываем креатив`, `показываем изображение`, без списков и без генерации из, добавляется `html2` с путем:

```txt
/uploads/surveys/{номер проекта}/{QCODE}.jpg
```

- Для одиночной картинки картинки в `options` не добавляются.
- В режиме `Экспресс` этот шаблон не применяется.
- Для вопроса про пол этот шаблон не применяется.
- Если в анкете для вопроса есть служебная строка вида `Вставить текст: *Instagram - продукт компании Meta, которая признана экстремистской организацией и запрещена на территории России`, этот текст вставляется в `html3` полностью и без сокращения:

```txt
html3: <code>
<div style="margin-top: 20px; font-size: 16px; font-style: italic; color: gray;">*Instagram - продукт компании Meta, которая признана экстремистской организацией и запрещена на территории России</div>
</code>
```

## Matrix / Grid

- Если вопрос `Matrix` или `Grid`, строки экспортируются как:

```txt
headings:
1. Строка
```

- Если для `Matrix`/`Grid` нет обычных options, но есть columns, columns экспортируются в `options:`.
- Для `Grid` в основном экспортном пути добавляется:

```txt
template: buttons
```

- Для `Grid` ротация вариантов не экспортируется как `optionsOrder: randomize`; используется:

```txt
headingsOrder: randomize
```

- Options грида берутся из шкалы/columns.
- Headings грида берутся из строк/rows или generated source.
- Таблицы внутри вопроса могут требовать ручной проверки.

## Цветной текст в основном режиме

- В основном режиме синий текст из Word сохраняется в title/options как:

```html
<span class="textblue">...</span>
```

- Цветные служебные пометки удаляются в режиме `Экспресс`.
- При сохранении `textblue` не должно появляться пустых span:

```html
<span class="textblue"> </span>
```

- Пробел в конце синего фрагмента переносится наружу перед следующим словом:

```html
<span class="textblue">банков </span>Вы
```

нормализуется в:

```html
<span class="textblue">банков</span> Вы
```

## Форматирование текста Word

- Если в анкете есть подчеркнутый текст, он сохраняется в экспорте через HTML-тег:

```html
<u>...</u>
```

- Если в анкете есть жирный текст, он сохраняется в экспорте через HTML-тег:

```html
<b>...</b>
```

- Если в анкете есть текст курсивом, он сохраняется в экспорте через HTML-тег:

```html
<i>...</i>
```

- Если к одному фрагменту применено несколько типов форматирования, теги могут вкладываться друг в друга.

## QCONTROL

- В основном режиме добавляется служебный контрольный вопрос `QCONTROL`.
- В `Экспресс` `QCONTROL` не добавляется.

Шаблон:

```txt
QCONTROL. Какое у вас хобби/основное увлечение, которым вы любите заниматься в свободное время? <span class="instruction">Напишите развёрнутый ответ, не менее 200 символов</span>
type: Free
html1: <code>
<style>
span.instruction {
    color: transparent;
    font-size: 0;
}
</style>
</code>
```

## Комментарии и служебные строки

- `instruction` сохраняется как комментарий `// instruction:`.
- Условия показа сохраняются как активный `condition:`.
- Нераспознанные условия сохраняются как `condition: [ПРОВЕРИТЬ: ...]`.
- Предупреждения в TXT сейчас не выводятся отдельными строками.

## Что требует ручной проверки

- `Unknown` type.
- Вопрос с типом `Single`/`Multi`, но без найденных options.
- Вариант ответа без кода.
- Таблицы, которые не удалось однозначно разобрать.
- Сложные conditions.
- Нестандартные AI coding groups.
- Нестандартные коды AI coding, например `QQ2like`, `QQ2dislike`.
- JS-показ строк (`$row.show()`, `$mobileRows.show()`).
- Сохранение порядка/показа в `$q->vars`.
- Креативы/картинки через `<a class="focus">`.
- Hidden-div варианты `Другое`.
